# AP Scout backend — AI-агроном

API для розпізнавання хвороб і шкідників сільськогосподарських культур за фото з поля: від зйомки та діагнозу до рекомендації препаратів, завдання механізатору та журналу обробок. Технічне завдання: `docs/ТЗ_AP_Scout_—_AI_агроном_для_розпізнавання_хвороб_і_шкідників.pdf`, архітектурний контракт (спільний з frontend): `docs/architecture.md`.

- NestJS 10, TypeORM, SQLite (better-sqlite3), Swagger на `/api/docs` (якщо увімкнено).
- Розпізнавання: Gemini (`@google/genai`) через інтерфейс `VisionProvider`; є `MockVisionProvider` для роботи без ключа.
- Клієнт — окремий проєкт `ap-scout-frontend` (Angular 21 PWA), який ходить сюди по HTTP.

## Запуск

Потрібен Node.js 20+.

```bash
npm install
cp .env.example .env       # лише якщо .env ще немає
npm run seed               # демо-ферма, користувачі, 3 поля, каталог, залишки
npm run start:dev          # http://localhost:3000
```

Збірка і тести: `npm run build`, `npm test`, `npm run test:e2e`.

| Що | Адреса |
|---|---|
| API | http://localhost:3000/api/v1 |
| Health | http://localhost:3000/api/v1/health |

Frontend у dev-режимі проксіює `/api` сюди; дозволені origin-и задає `CORS_ORIGINS` у `.env`.

### Демо-входи

Пароль береться з `DEMO_USER_PASSWORD` у `.env` (у `.env.example` — `change-me-demo-password`). У production демо-користувачі не створюються, якщо не задано `AUTH_SEED_DEMO_USERS=true` та `DEMO_USER_PASSWORD`.

| Роль | Email |
|---|---|
| Скаут (S) | `scout@apscout.demo` |
| Головний агроном (C) | `chief@apscout.demo` |
| Механізатор (M) | `mechanic@apscout.demo` |
| Експерт (E) | `expert@apscout.demo` |

## Ключ Gemini

Ключ задається лише в `.env`:

```
AI_PROVIDER=gemini
GEMINI_API_KEY=<ваш ключ>
GEMINI_MODEL=gemini-3.5-flash
```

- `AI_PROVIDER=mock` — розробка без мережі та ключа (детермінована відповідь `MockVisionProvider`).
- Якщо `GEMINI_API_KEY` порожній, застосунок автоматично переходить на mock і пише попередження в лог.
- `.env` не комітиться і не логується; усі ключі описані в `.env.example`.
- Модель `gemini-2.5-flash` Google вже не видає новим користувачам; якщо у вашому `.env` ще вона, замініть `GEMINI_MODEL`.

## Відомі відхилення від ТЗ

- Веб-PWA замість нативного застосунку; роль «фермер» (етап 2) не реалізована.
- Довідники (діагнози, препарати, пороги) містять DEMO-дані; реєстраційні номери препаратів порожні до завантаження Державного реєстру. Еталонні фото — один плейсхолдер на діагноз замість 2-3 реальних.
- Затверджує довідники роль «головний агроном» (окремої ролі агронома-технолога в архітектурі немає).
- Карантинний інтервал (FR-14) оцінюється за датою сівби та типовою тривалістю циклу культури; без дати сівби видається попередження, а не виключення препарату. Порогові показники в % площі листка не оцінюються (лише попередження).
- Сумісність баків між препаратами в рекомендації лише попередження.
- Залишки: без перерахунку одиниць; прострочені партії ще враховуються; CSV-імпорт залишків не реалізований.
- Розпізнавання: калібрування ймовірностей приблизне (температурне), без навчання на власних даних; мультикадрова агрегація за замовчуванням `mean_log_prob`.
- Голосові нотатки зберігаються, але не транскрибуються.
- Черга уточнень, ліміт спроб входу та кеш погоди зберігаються в пам'яті одного екземпляра.
- Повільні виклики Gemini: повтори без затримки; у разі збою провайдера діагноз позначається як «не впевнений» з причиною `provider_error`.
- Режим економії заряду не реалізований (лише «сонячний» режим і великі цілі натискання).
- Текст ТЗ у PDF не вдалося витягнути автоматично, тому відповідність формулюванням звірялась за `docs/architecture.md`.
